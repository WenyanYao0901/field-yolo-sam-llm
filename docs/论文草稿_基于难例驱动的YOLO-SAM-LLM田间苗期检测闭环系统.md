**摘要：** 苗期精准除草依赖对玉米苗与杂草的可靠识别，但田间场景存在小目标、遮挡粘连、光照变化与类间外观相近等问题，单一检测模型往往在不确定样本上误差集中，而全量调用分割大模型成本高、且难以直接服务农事决策。本文提出一种职责解耦的协同检测与质检闭环框架：以 YOLO 作为实时检测与 mAP 验收主体，负责提供类别、置信度与初检框；以难例挖掘策略筛选不确定框与拥挤场景，仅对预算内样本调用 Segment Anything Model（SAM）进行 box-prompt 掩膜精炼并以掩膜外接框回写定位；再以大语言模型（LLM）消费结构化检测摘要，生成不改写检测结果的质检意见与中文农事报告。框架显式规定：类别与置信度始终来自 YOLO，框仅在 SAM 成功时替换，且每条结果保留 `refined_by` 溯源标记；LLM 不参与框与类别修改，也不进入检测指标。该设计在保证检测可复现验收的同时，将昂贵视觉大模型算力集中到难例，并把自然语言质检与业务报告从指标链路中隔离出来。本文给出系统架构、难例评分、框级融合规则、标签回灌机制与实验协议，可为田间智能监测与半自动标注提供可落地的方法模板。

## 1 引言

玉米是我国重要的粮食与饲料作物。苗期杂草与作物争光、争水、争肥，若不能及时区分并实施靶向管理，会显著影响后期产量与投入产出比。随着植保无人机、田间机器人与高通量成像设备的普及，基于计算机视觉的作物–杂草自动识别成为精准农业的关键环节之一。与温室或受控环境不同，真实田间图像往往同时包含：目标尺度小、叶片相互遮挡、土壤背景复杂、光照与阴影剧烈变化，以及阔叶杂草与禾本科杂草在纹理上的混淆。这些问题使得“只追求平均 mAP”的单一检测模型在部署时仍会出现局部失效——错误经常集中在置信度中间带、目标密集区和疑似漏检图上。

近年来，以 YOLO 系列为代表的单阶段目标检测器在农业目标检测中得到广泛应用，具备速度与精度较均衡的优势，适合作为田间实时感知的主干。与此同时，以 Segment Anything Model（SAM）为代表的视觉基础模型展现出强大的交互式分割与零样本泛化能力，可通过点、框等提示生成高质量掩膜，为定位精炼与半自动标注提供新工具。另一方面，大语言模型（LLM）在结构化信息理解、风险归纳与自然语言报告生成方面进展迅速，为“检测结果 → 可执行农事建议”的最后一公里提供了接口。然而，若简单地将 YOLO、SAM 与 LLM 堆叠，容易出现三类问题：（1）全量图像调用 SAM 带来不可接受的算力与时延；（2）用分割或语言模块改写类别会破坏检测验收口径，使 mAP 不可解释；（3）LLM 若直接“编造”坐标与类别，会引入不可控幻觉，损害系统可信度。

针对上述矛盾，本文围绕工程系统 `field-yolo-sam-llm` 所实现的方法，提出并系统阐述一种**难例驱动、职责解耦**的田间苗期协同检测与质检闭环：

1. **YOLO 主责检测验收**：输出类别、置信度与初检框，系统级检测性能以 YOLO 的 Precision、Recall、mAP 为准；  
2. **难例驱动的 SAM 精炼**：根据不确定置信区间、低置信密度与目标拥挤度计算难例分数，仅对不确定框或难例图调用 SAM，用掩膜外接框改善定位，**不改变类别与置信度**；  
3. **LLM 结构化质检与报告**：仅输入检测摘要（非原图），强制输出 JSON 质检字段与 Markdown 报告，**禁止改写框与类别**，从而把业务可读性与检测指标隔离。

本文的主要贡献可概括为：

- 提出面向田间苗期三类目标（玉米苗、阔叶杂草、禾本科杂草）的 YOLO–SAM–LLM 闭环架构，并给出可复述的框级融合与溯源规则；  
- 设计可解释的难例评分函数与预算分配策略，使 SAM 算力集中于不确定与拥挤样本；  
- 建立 SAM 精炼标签回写（YOLO txt）机制，支持半自动标注与迭代再训练；  
- 给出面向二区及以上期刊投稿所需的实验协议、消融设计与评价指标体系（需在真实数据上完成实测）。

从产业与科研双重需求出发，苗期识别系统还应满足四点工程约束：其一，推理链路需可在田间移动平台或巡田后处理节点上稳定运行；其二，指标口径必须可复现，便于不同批次模型横向比较；其三，标注成本必须可控，因为农业目标具有季节性，每年都需补充新域数据；其四，输出必须能被非算法背景的农技人员理解，否则模型难以进入真实决策闭环。基于上述约束，简单追求排行榜式的检测精度并不足够，构建“检测—精炼—质检—回灌”的完整方法链条更具实际价值。

全文结构如下：第 2 节回顾相关工作；第 3 节详述方法；第 4 节给出实验协议与结果框架；第 5 节讨论；第 6 节总结与展望。

## 2 相关工作

### 2.1 农业场景下的目标检测

作物与杂草检测长期是农业计算机视觉的核心任务。传统方法依赖颜色指数、纹理特征与机器学习分类器，对光照与背景变化敏感。深度学习兴起后，两阶段检测器（如 Faster R-CNN）与单阶段检测器（如 SSD、YOLO 系列）被广泛用于杂草识别、病虫害检测与果实计数。YOLO 系列因端到端训练与实时推理特性，成为田间边缘部署的常见选择。已有研究通过改进骨干网络、注意力机制、小目标检测头或数据增强，提升复杂背景下的检测精度。但多数工作仍将系统终点定义为“更高的 mAP”，对不确定样本的后续处理、标注成本与农事可解释输出关注不足。

### 2.2 分割基础模型与检测精炼

SAM 等视觉基础模型通过大规模掩膜预训练，具备强大的提示式分割能力。在农业中，SAM 已被用于叶片分割、果实实例分割与标注加速。将检测框作为 box prompt 输入 SAM，可得到更贴合目标轮廓的掩膜，进而由掩膜外接矩形回写更紧的定位框。需要强调的是：SAM 本身通常不直接承担细粒度农业类别判别；若用分割结果反推类别，反而可能引入新的错误来源。因此，本文坚持“SAM 只精炼几何、不改分类”的原则，使其服务定位与标注，而非替代检测器。

### 2.3 难例挖掘与主动学习

主动学习与难例挖掘旨在把有限标注/计算预算分配到信息量大的样本上。常见策略包括低置信采样、熵采样、委员会分歧与密度聚类等。田间部署中，全量精炼不现实，因此难例驱动具有工程必然性。本文将难例信号具体化为三类可计算特征：不确定置信带、低置信框数量与目标拥挤度，形成透明可调的打分函数，便于与农艺人员共同设定阈值。

### 2.4 大语言模型在农业决策中的应用

LLM 已被探索用于农业问答、病虫害知识检索与田间管理建议生成。若直接把图像或冗长检测日志丢给 LLM，既昂贵又难控幻觉。更稳健的做法是：先由视觉模型完成感知，再将结构化摘要交给 LLM 做归纳、风险提示与报告润色。本文采用“摘要进、JSON 出、禁止改框”的约束式调用，使 LLM 定位为质检助手与报告生成器，而非第二检测器。

### 2.5 精准除草与处方图生成中的感知需求

从农艺作业链路看，苗期检测并非孤立的视觉任务，而是变量喷雾、机械除草与人工复核不均衡配置的上游输入。典型流程为：巡田成像 → 目标识别与密度估计 → 生成杂草压力图/处方图 → 执行机构按处方作业 → 效果复核。其中，感知模块若在作物行上出现系统性误检，会导致“伤苗”；若在杂草聚集区漏检，则会导致“漏除”。二者造成的经济与生态代价不对称：伤苗直接损害产量，漏除增加后续防治成本与抗性风险。因此，系统不仅需要报告平均精度，还需要暴露高风险图像、支持分层复核，并保留每条检测的来源标记以便事后追溯。本文引入的难例清单与 LLM 质检报告，正是为这一业务约束服务：把有限人工注意力引导到最可能出错的样本上，而不是要求农技人员逐张审阅全部航拍或地面图像。

### 2.6 多模型协同的常见范式及其局限

现有多模型协同大致可分为三类。第一类是“检测+分割串联”，即检测框裁剪后送入分割网络获得掩膜；其优点是实例边界清晰，缺点是对每一检出目标都调用分割，成本随目标数线性增长，且分割网络往往需要额外农业掩膜标注。第二类是“教师–学生/伪标签自训练”，用高容量模型或强增强产生伪标签再蒸馏；该方法能扩大数据，但对阈值与噪声标签敏感，田间类间相似时易发生确认偏差。第三类是“多模态大模型端到端问答”，直接询问图像中作物与杂草位置；其交互友好，但坐标稳定性、类别细粒度与实时性仍难满足机载/车载闭环控制，且评测协议尚未像目标检测一样标准化。本文采取第四条路径：以成熟检测器守住实时性与 mAP 口径，以基础分割模型按预算精炼几何，以语言模型守住可解释质检，三者通过明确接口协议连接，而不是融合成一个不可审计的黑箱。

### 2.7 与本文的差异

相较于“仅 YOLO 检测”“YOLO+全图分割”或“端到端多模态大模型替代检测”的路线，本文强调**指标口径清晰**与**成本可控**：检测验收只认 YOLO；SAM 按难例预算调用；LLM 不污染 mAP。与单纯主动学习论文相比，本文将难例分数同时用于计算预算分配与人工复核排序，形成“训练期可回灌、推理期可质检”的双重用途。这一分工更契合田间工程落地与学术评价的双重要求。

## 3 方法

### 3.1 问题定义与系统目标

给定田间 RGB 图像集合 \(\mathcal{I}=\{I_n\}_{n=1}^{N}\)，目标是识别三类实例：玉米苗（maize）、阔叶杂草（broadleaf）与禾本科杂草（grass）。对每张图像，系统输出检测集合

\[
\mathcal{D}(I)=\{(b_i,c_i,s_i,r_i)\}_{i=1}^{M},
\]

其中 \(b_i\) 为边界框，\(c_i\) 为类别，\(s_i\) 为置信度，\(r_i\in\{\text{yolo},\text{sam}\}\) 表示框是否经 SAM 精炼。同时，系统输出质检结构 \(\mathcal{Q}\) 与中文报告 \(\mathcal{R}\)。约束为：

- 检测评价指标仅基于 \((b_i,c_i,s_i)\) 中由 YOLO 决定的 \(c_i,s_i\) 与最终框 \(b_i\) 计算时可分开报告“YOLO 原框”与“融合后框”的定位差异；**分类指标以 YOLO 为准**；  
- \(\mathcal{Q},\mathcal{R}\) 不得回写修改 \(\mathcal{D}\)。

### 3.2 总体架构

系统由四个阶段组成，形成可复现闭环：

**阶段 A：YOLO 初检。** 加载田间微调或预训练权重，对输入图像进行检测，得到初检列表（类别、置信度、xyxy 框），并导出 `predictions_yolo.json`。

**阶段 B：难例挖掘。** 复用初检结果，避免二次推理；对每张图计算难例分数与原因，导出 `hard_examples.json`。

**阶段 C：SAM 选择性精炼。** 对满足条件的框以 YOLO 框为 prompt 生成掩膜，提取外接矩形并写回；保存 `labels_sam/`、`sam_masks/` 与合并后的 `final_results.json`、可视化 `vis/`。

**阶段 D：LLM 质检报告。** 汇总检测与难例摘要，调用 Chat Completions 接口，解析强制 JSON，写出 `qc_report.json` 与 `report.md`。

该流水线对应工程入口 `main.py run` 与编排模块 `src/pipeline/run.py`。

### 3.3 YOLO 检测主干

采用 Ultralytics YOLO（默认 YOLOv8s，可替换为 YOLO11 等）作为检测器。训练数据采用标准 YOLO 格式：

- 图像：`data/images/{train,val,test}/`  
- 标签：`data/labels/{train,val,test}/`，同名 `.txt`  
- 每行：`class_id cx cy w h`（相对图像宽高归一化到 \([0,1]\)）

类别编号在配置中连续定义，例如：

\[
0:\ \text{maize},\quad 1:\ \text{broadleaf},\quad 2:\ \text{grass}.
\]

需要特别注意：若标注工具（如 Label Studio）导出的 `classes.txt` 顺序与训练配置不一致，必须统一映射，否则类别语义错位将直接导致指标失效。推理阶段默认置信度阈值 \(\tau_{\text{conf}}=0.25\)、NMS IoU 阈值 \(0.45\)、输入尺度 \(640\times640\)。设备选择遵循 CUDA → MPS → CPU 的自动降级策略，便于实验室服务器与本地 Mac 开发环境切换。

YOLO 在本框架中的角色被明确为：**位置初估 + 类别判别 + 置信度校准信号源**。后续模块可以改善框几何或解释结果，但不得静默篡改 YOLO 的类别决策用于“刷高”业务展示而不改验收口径。

### 3.4 难例评分与筛选

对图像 \(I\) 的检测集合 \(\mathcal{D}\)，设置信度集合为 \(\{s_i\}\)。定义不确定区间 \([\ell,h)=[0.25,0.6)\)（可配置）。统计：

- 不确定框数 \(U=\lvert\{i\mid \ell\le s_i<h\}\rvert\)  
- 低置信框数 \(L=\lvert\{i\mid s_i<\ell\}\rvert\)  
- 拥挤标志 \(D=\mathbb{I}[\lvert\mathcal{D}\rvert\ge 8]\)

难例分数定义为

\[
H(I)=1.0\cdot U+0.5\cdot L+2.0\cdot D.
\]

当 \(H(I)\ge \theta_H\)（默认 \(\theta_H=0.45\)）时，将该图标记为**难例图**。对单框，若 \(s_i\in[\ell,h)\)，则标记为**不确定框**。SAM 触发规则为：

\[
\text{Refine}(i)=\mathbb{I}[s_i\in[\ell,h)]\ \lor\ \mathbb{I}[H(I)\ge\theta_H].
\]

即：不确定框必精炼；难例图上的全部框尝试精炼。对“完全无检测”的图像，打分返回 \(H=0\) 并给出“可能漏检”原因，建议人工抽检；但默认不因空检自动调用 SAM（因缺乏有效 box prompt）。这一设计把漏检问题留给质检与人工复核，而不是用分割模型空想目标。

难例机制的直观含义是：把计算预算从“模型已经很确定的简单图”转移到“模型正在犹豫或场景拥挤”的样本上，这与主动学习中的不确定性采样一致，但形式更简单、阈值可与农艺人员共同解释。

### 3.5 SAM 框提示精炼与回写

对需要精炼的检测框 \(b^{\text{yolo}}\)，加载 SAM（默认 ViT-B 权重）并以该框为 prompt 生成二值掩膜 \(m\)（`multimask_output=False`）。若掩膜有效且面积超过最小阈值，则计算其轴对齐外接矩形 \(b^{\text{sam}}\)，并用其替换原框；同时记录 SAM 内部分数（如可用）与掩膜可视化。若精炼失败，则保留 YOLO 原框。

**框级融合规则（可直接复述）：**

1. 类别 \(c_i\)：始终取 YOLO；  
2. 置信度 \(s_i\)：始终取 YOLO；  
3. 框 \(b_i\)：若该框被选中且 SAM 成功，则 \(b_i=b^{\text{sam}}\)，否则 \(b_i=b^{\text{yolo}}\)；  
4. 溯源标记 \(r_i\in\{\text{yolo},\text{sam}\}\)。

将精炼后的框按 YOLO 归一化格式写入 `labels_sam/*.txt`，可回灌 Label Studio 或本地标注库，形成“检测 → 难例精炼 → 人工确认 → 再训练”的数据飞轮。可视化中可用不同颜色区分 YOLO 原框与 SAM 精炼框，便于质检人员快速审阅。

从方法角度看，该步骤把 SAM 当作**条件几何校正器**：输入是检测器给出的空间假设，输出是更贴合实例的轮廓投影框。由于类别锁定，精炼不会把“玉米”改成“杂草”，从而避免分割误差污染分类评价。

### 3.6 LLM 结构化质检与报告生成

在得到 YOLO 初检、难例清单与最终融合结果后，系统构造结构化摘要，字段包括：图像数量、总检测数、类别统计、难例图像列表（截断前 50）、每图统计（截断前 100）等。摘要**不包含原图像素**，以降低带宽、保护隐私，并减少多模态幻觉面。

LLM（默认 DeepSeek `deepseek-chat`，可替换兼容 OpenAI 协议的模型）在系统提示中被约束为“田间质检助手”，要求：

- 不得编造坐标或类别；  
- 只能基于给定摘要做风险归纳与建议；  
- 输出必须可解析为 JSON，包含 `qc` 与 `report_md`；  
- `qc` 含 `suspicious_images`、`risk_points`、`review_suggestions` 等字段；  
- `report_md` 为中文 Markdown，覆盖检测概况、类别统计、风险与农事建议。

解码温度设为较低值（如 \(0.2\)），并兼容纯 JSON 与代码块包裹的 JSON。解析失败时记录错误而不中断视觉链路，保证检测主路径稳健。

该设计的关键原则是：**语言层服务解释与流程质检，视觉层服务可度量感知**。对学术评价而言，可单独报告 LLM 质检与人工审核的一致率、可疑图召回率与报告可用性评分，而不将其混入 mAP。

### 3.7 半自动标注与再训练闭环

完整业务闭环建议如下：

1. 采集田间苗期图像，按地块/日期分层；  
2. 使用 Label Studio 等工具完成 YOLO 格式标注，严格对齐类别顺序；  
3. 训练 YOLO，得到 `best.pt`；  
4. 对未标注或新采集批次运行闭环流水线；  
5. 人工审核 `vis/` 与 `labels_sam/`，确认后并入训练集；  
6. 周期性再训练，监控 val 集 mAP 与田间抽检错误类型。

该闭环把 SAM 从“一次性分割展示”升级为“可持续降低标注成本的生产力工具”，并把 LLM 报告作为班组作业与监管留痕的接口。

### 3.8 算法伪代码

```
输入: 图像目录 S, YOLO权重 W, SAM权重 Φ, 阈值 (τ, ℓ, h, θ_H)
输出: final_results, qc_report, report_md

model ← LoadYOLO(W)
sam   ← LoadSAM(Φ)
for I in ListImages(S):
    D ← Detect(model, I, conf=τ)
    H, reason ← ScoreHard(D, ℓ, h)
    hard ← (H ≥ θ_H)
    D' ← []
    for det in D:
        if Uncertain(det.s, ℓ, h) or hard:
            m ← SAM_BoxPrompt(sam, I, det.box)
            if Valid(m):
                det.box ← BBox(m); det.refined_by ← "sam"
            else:
                det.refined_by ← "yolo"
        else:
            det.refined_by ← "yolo"
        D'.append(det)   # 类别与置信度始终来自 YOLO
    Save(D'), Visualize(I, D')
summary ← BuildSummary(all D', hard list)
(qc, report_md) ← LLM_Review(summary)  # 不回写 D'
```

### 3.9 输出产物与可追溯性设计

闭环一次运行在输出目录中固化多层产物，便于论文复现与工程审计：

1. `predictions_yolo.json`：记录未经精炼的检测原语，作为分类与置信度的“事实源”；  
2. `hard_examples.json`：记录每图难例分数、原因字符串、不确定框计数与拥挤标志，支持阈值复盘；  
3. `final_results.json`：融合后的最终检测，每条含 `refined_by` 字段；  
4. `labels_sam/` 与 `sam_masks/`：YOLO 格式标签与掩膜图，服务标注回灌与定性分析；  
5. `vis/`：叠加可视化，区分不同精炼来源；  
6. `qc_report.json`、`report.md`、`summary.json`：质检结构、中文报告与流水线级统计。

可追溯性体现在：任意最终框都能回溯到 YOLO 初检记录；若框被 SAM 替换，仍保留原类别与置信度；若质检指出某图高风险，可对照难例原因与可视化进行人工裁决。该设计使系统不仅“能检测”，而且“能被追问错在哪一层”。

### 3.10 与变量喷雾决策的接口（方法层扩展）

虽然本工程当前输出以检测与报告为主，但方法上可自然对接处方图生成。设图像对应地面分辨率为 \(g\)（米/像素），将图像划分为网格单元 \(\{u_k\}\)，则单元杂草压力可定义为

\[
P(u_k)=\sum_{i:\,b_i\cap u_k\neq\emptyset} w(c_i)\,s_i\,A(b_i\cap u_k),
\]

其中 \(w(c)\) 为类别权重（例如阔叶与禾本科可设不同防治优先级），\(A(\cdot)\) 为相交面积。仅当单元内存在高置信作物框时，可对重叠杂草检测施加“保苗约束”，降低误喷概率。LLM 报告则可输出该地块的文字化风险摘要，供农艺师在确认处方前快速浏览。需要强调：处方执行阈值属于作业策略，不应反向改写检测标签；本文坚持感知与决策分层，避免把喷雾策略误差计入检测 mAP。

### 3.11 复杂度与预算分析

记 YOLO 单图耗时为 \(T_y\)，SAM 单次框提示耗时为 \(T_s\)，平均每图检出 \(m\) 个目标，难例触发使实际精炼框数为 \(m_r\)（\(m_r\le m\)）。忽略 LLM 批处理摊销时，单图视觉耗时近似为

\[
T \approx T_y + m_r\,T_s.
\]

全图精炼对应 \(m_r=m\)，难例驱动对应 \(m_r=\rho m\)，其中 \(\rho\) 为精炼率。只要 \(\rho\) 明显小于 1，且难例子集上定位收益显著，系统就能在精度–时延帕累托前沿上取得更优工作点。LLM 调用按批次摘要计费，与图像分辨率解耦，适合作为异步质检服务，而不阻塞田间实时检测线程。

### 4.1.1 采集与标注作业规范（建议写入论文补充材料）

为降低领域偏移并提高可复现性，数据采集建议固定以下元数据字段：采集日期、生育期（叶龄）、地理网格或地块编号、相机型号与焦距、离地高度、天气与光照备注、是否灌溉后拍摄。地面拍摄时保持镜头近似垂直地面，避免过大透视造成尺度标注不稳定；无人机拍摄时记录航高与重叠度，使测试集可按航高分层评估。标注规程上，框应尽量贴合可见植株主体，对严重遮挡目标标注可见部分并打遮挡属性；当玉米苗与杂草叶片交叉时，按实例中心归属类别，避免“一个框装两类”。每批次导出后运行自动检查：空标签比例、类别直方图、框宽高分布异常值、以及 `classes.txt` 与 `field.yaml` 一致性。只有通过质控的数据才进入训练池，这样才能保证后续难例挖掘反映的是模型不确定性，而不是标注噪声。

**检测基线：** YOLOv5s/YOLOv8s/YOLO11s、RT-DETR 等同量级模型。

|----------|------|----------|--------------|

## 5 讨论

### 5.1 为什么必须职责解耦

在多模型系统中，若允许 SAM 或 LLM 修改类别，短期展示效果可能“更好看”，但会破坏科学评价与工程追责：一旦出现误喷雾或漏除草，无法判断错误来自检测器、分割器还是语言层。本文把 mAP 验收锚定在 YOLO，把几何精炼与语言质检分别度量，更符合可审计智能系统的要求。

### 5.2 难例驱动的成本意义

SAM 推理显著重于 YOLO。若田间每日处理数万张图像，全量分割既不经济也不必要。难例分数把预算导向不确定与拥挤区域，等价于在精度–成本平面上选择工作点。阈值 \((\ell,h,\theta_H)\) 可根据植保窗口紧急程度动态调整：作业高峰可提高阈值以降低调用率，科研标注阶段可降低阈值以提升召回。

### 5.3 LLM 的边界

LLM 擅长归纳与表达，但不应被当作检测器。本文仅输入摘要并禁止编造坐标，是降低幻觉的工程约束。未来可引入检索增强（当地草谱、农药标签知识库）以提升建议专业性，但仍需人工确认高风险操作。实践中还应防止两类误用：一是把报告中的定性措辞直接当作自动喷雾开关；二是在摘要被过度截断时，仍要求模型给出精细到垄行的结论。前者属于决策越权，后者属于信息不足下的过度推断。合理用法是：LLM 输出“哪些图要看、可能有什么风险、建议如何复核”，人完成最终确认。对科研论文而言，报告质量应用独立标注的质检标签来评估，而不是用检测 mAP 间接证明。

### 5.4 类别体系与数据质量

农业检测论文的常见失败点并非网络结构，而是类别定义漂移与标注不一致。Label Studio 导出顺序与 `field.yaml` 不一致时，模型会“学错名字”。建议在数据管道中强制校验 `classes.txt` 与训练配置的双射关系，并在论文中明确类别操作定义（形态学特征与生育期范围）。以本项目三类体系为例：玉米苗强调作物行内目标与叶形特征；阔叶杂草覆盖叶片宽阔、叶脉网状的常见田间杂草集合；禾本科杂草覆盖与作物苗期更易混淆的窄叶类型。若某地区优势杂草物种特殊，应在不破坏评价可比性的前提下增加子类，或在讨论中声明超类合并规则，避免审稿阶段因类别含混被质疑。

### 5.5 伦理、安全与部署

田间数据可能含地理位置与农户信息，摘要上传云端 LLM 前应做脱敏与合规评估；API 密钥不得硬编码入库。边缘部署可仅运行 YOLO，把 SAM/LLM 放在云端或工位复核节点，形成端–边–云协同。

### 5.6 对标二区期刊的差距与补强清单

要达到计算机+农业交叉方向常见二区期刊（如 *Computers and Electronics in Agriculture*、*Biosystems Engineering*、部分 Remote Sensing/农业信息类期刊）的审稿预期，通常需要：

1. **足够规模且划分严格的真实数据集**（含采集协议与标注一致性检验）；  
2. **完整基线与消融**（精度、定位、效率、成本）；  
3. **田间或接近田间的验证**（跨地块、跨日期泛化）；  
4. **清晰贡献**（不是简单拼接模型，而是可验证的难例预算与融合规则）；  
5. **开源或可复现细节**（超参、种子、硬件、数据示例）。

当前工程已具备方法骨架与可运行闭环，具备写成方法论文的基础；缺口主要在数据与系统实验，而非再堆叠更多模型名称。

### 5.7 方法创新点的审稿表述建议

向应用类期刊投稿时，创新不宜表述为“首次把三个热门模型放在一起”，而应强调可验证机制：

- **机制创新**：提出面向田间检测置信特征的难例评分与触发规则，将基础分割模型的调用从“全量”降为“预算内”；  
- **评价创新**：明确三级产物的评价边界——检测 mAP、精炼子集 IoU、质检一致率——避免指标混用；  
- **系统创新**：给出标签回灌与中文质检报告接口，打通“模型—标注—农艺复核”闭环。

这样的表述更符合二区期刊对“problem–method–evidence”完整性的要求，也降低被审稿人批评为“工程拼盘”的风险。

### 5.8 局限性

本文方法仍存在若干局限。第一，难例分数依赖置信度校准质量；若模型严重过自信，不确定区间可能失效，需要温度缩放或可靠性图辅助。第二，SAM 对提示框质量敏感，当 YOLO 框严重偏移或多目标挤在同一框内时，掩膜可能粘连，外接框未必优于原框，故融合阶段必须保留失败回退。第三，三类标签体系相对粗粒度，实际田间杂草物种远多于此，开集与长尾物种识别尚未解决。第四，LLM 报告的专业性受提示词与领域知识限制，不能替代持证农艺师的处方签字。第五，当前原型数据规模不足以支撑强泛化结论，任何性能数字都必须等待完整实验。

### 5.9 应用场景与推广条件

本框架优先适用于以下场景：玉米（或形态相近的旱作）苗期巡田、科研样地高通量表型、植保服务组织的作业前复核。推广到水稻、小麦等作物时，需重建类别体系与拍摄几何（俯视高度、行距、叶龄）。对算力受限的边缘设备，可仅部署 YOLO，将难例图像上传至机巢或云端执行 SAM/LLM；对无外网环境，可用本地小参数语言模型生成简化质检清单。成功落地的关键不在模型更大，而在数据采集规范、类别定义稳定、以及农艺人员愿意使用报告去分配复核工时。

## 6 结论与展望

本文面向玉米苗期精准管理需求，提出难例驱动的 YOLO–SAM–LLM 协同检测与质检闭环方法。YOLO 承担实时检测与指标验收；SAM 在不确定与拥挤预算内精炼几何定位并回写标签；LLM 基于结构化摘要生成质检意见与中文农事报告且不改写检测结果。该职责解耦框架在保持评价口径清晰的同时，为算力分配与人机协同复核提供了可落地路径。

从计算机科学角度看，本文贡献在于把基础视觉模型与大语言模型嵌入经典检测流水线时，给出了可审计的接口契约与预算分配算法；从农业工程角度看，贡献在于把检测系统的输出从“框和分数”延伸到“可复核的风险清单与中文报告”，更贴近植保作业组织方式。两者结合，形成面向精准农业的感知–质检闭环模板。

未来工作包括：（1）在大规模真实田间数据上完成完整实验与跨域测试；（2）引入更精细的主动学习策略与伪标签自训练（需严格过滤）；（3）探索轻量化 SAM/移动端检测以支持机载实时；（4）将质检报告对接处方图与变量喷雾执行链路，形成感知–决策–作业闭环；（5）扩展至多作物与多杂草体系，并研究开集杂草识别；（6）开展人因实验，量化 LLM 报告对农艺师复核效率与决策质量的影响。

总之，田间智能检测的下一步未必是无限制地扩大模型规模，而是在明确责任边界的前提下，让昂贵模型只出现在真正需要的地方，并让人能够理解、质疑与纠正模型。本文提出的难例驱动 YOLO–SAM–LLM 闭环，正是朝这一目标的一次系统化尝试。

## 7 软件实现与可复现实验组织

为便于同行复现，本文将软件实现组织为四层：`detect`（YOLO 训练与推理）、`assist`（难例、SAM、LLM）、`pipeline`（闭环编排）、`utils`（配置与 I/O）。用户可通过统一命令行完成：样本准备、仅检测、训练、以及完整 `run` 闭环。复现实验时建议固定随机种子、记录 Ultralytics 与 PyTorch 版本，并保存 `args.yaml` 与 `results.csv`。对 LLM 部分，应在论文中声明模型名称、接口基址、温度与提示词版本号；若期刊要求，可将提示词全文放入补充材料。涉及云端 API 的实验需说明网络环境与失败重试策略，避免把偶发网络错误解释为方法差异。

在组织对比实验时，推荐采用“同一测试集、同一硬件、同一 YOLO 权重”控制变量：先冻结检测器，只改变是否调用 SAM 与调用策略，以分离定位模块贡献；再在固定视觉结果上评估不同 LLM 或提示词对质检指标的影响。这样可以防止把检测器升级带来的增益误记到 SAM 或 LLM 头上。对于消融 A4（阈值敏感性），应以精炼率 \(\rho\) 为横轴、以难例子集 IoU 或人工复核工作量为纵轴绘制曲线，直观展示预算–收益权衡，这往往比单点最优超参更有说服力。

若条件允许，公开一个去标识的迷你子集（例如 100 张图与标签）以及完整配置，将显著提高稿件可信度。即使完整田数据因产权不能开源，也应在文中提供获取途径或统计描述（各类别实例数、图像分辨率分布、地块数）。对中文初稿转化为英文投稿时，还需统一术语：maize seedling、broadleaf weed、grass weed、hard example mining、box-prompt refinement、quality inspection report 等，并避免把“闭环”简单译成缺乏技术含义的空泛词，而应译为 closed-loop detection–refinement–inspection pipeline。

**Title:** Hard-Example-Driven YOLO–SAM–LLM Closed Loop for Seedling-Stage Crop–Weed Detection and Quality Inspection in Precision Agriculture

**Abstract (draft):** Seedling-stage weed management requires reliable discrimination among maize seedlings, broadleaf weeds, and grass weeds under occlusion, scale variation, and appearance ambiguity. We present a responsibility-decoupled closed-loop framework in which YOLO serves as the real-time detector and the sole source of classification confidence for mAP evaluation; a transparent hard-example score allocates Segment Anything Model (SAM) refinement only to uncertain boxes or crowded images, replacing boxes with mask-derived bounding boxes without altering class labels; and a large language model consumes structured summaries—not raw images—to produce JSON quality-control findings and Chinese agronomic reports without rewriting detections. The design clarifies evaluation boundaries, controls foundation-model cost, and enables SAM label feedback for semi-automatic annotation. We detail the scoring function, fusion rules, and a journal-oriented experimental protocol for future large-scale field validation.
